# 반도체 시료 생산주문관리 시스템 — Product Requirements Document

**버전** 1.0  
**작성일** 2026-05-08  
**대상 시스템** SampleOrderSystem

---

## 1. 배경 및 목적

### 1.1 문제 정의

반도체 회사 S-Semi는 웨이퍼 공정을 통해 생산한 시료(Sample)를 연구소, 팹리스 업체, 대학 연구실 등에 납품한다. 주문량 급증으로 기존 엑셀·메모장 기반 관리 방식에서 다음 문제가 발생했다.

- 주문 처리 여부를 추적하지 못해 누락·중복 발생
- 공정 완료 시점을 예측할 수 없어 납기 관리 불가
- 재고가 충분함에도 불필요한 생산 공정이 가동되어 자원 낭비

### 1.2 목적

체계적인 시료 생산주문관리 시스템을 개발하여 주문 접수부터 출고까지 전 과정을 가시화하고, 재고와 생산 현황을 실시간으로 파악할 수 있게 한다.

## 2. 사용자 및 역할

| 역할 | 설명 | 권한 범위 |
|------|------|-----------|
| 주문 담당자 | 고객 요청을 시스템에 등록 | 시료 등록·조회·검색, 주문 접수 |
| 생산 담당자 | 주문 승인·거절 및 출고 처리 | 주문 승인/거절, 생산라인 관리, 출고 처리 |

> 고객(시료 요청자)은 이번 시스템 범위에서 제외된다.

---

## 3. 주문 상태 흐름

```
주문 접수
   │
   ▼
RESERVED ──── 거절 ────► REJECTED  (모니터링 제외)
   │
   │ 승인
   ▼
재고 충분? ──YES──► CONFIRMED ──► RELEASE
   │                                (출고완료)
   NO
   │
   ▼
PRODUCING ──── 생산 완료 ──► CONFIRMED
(생산 큐 등록)
```

| 상태 | 의미 |
|------|------|
| RESERVED | 주문 접수 완료, 승인 대기 |
| REJECTED | 주문 거절 (비정상 종료, 모니터링 제외) |
| PRODUCING | 승인 완료, 재고 부족으로 생산 중 |
| CONFIRMED | 승인 완료, 출고 대기 |
| RELEASE | 출고 완료 |

## 4. 기능 요구사항

### 4.1 메인 메뉴

| 메뉴 항목 | 설명 |
|-----------|------|
| 시료 관리 | 시료 등록, 목록 조회, 이름 검색 |
| 주문 (접수 / 승인 / 거절) | 주문 접수 및 승인·거절 처리 |
| 모니터링 | 상태별 주문 수 및 시료별 재고 현황 |
| 출고 처리 | CONFIRMED 주문 출고 실행 |
| 생산 라인 | 생산 중인 시료 및 대기 큐 확인 |

- 메인 메뉴에서 전체 시료에 대한 요약 정보를 함께 표시한다.

---

### 4.2 시료 관리

시료(Sample)는 시스템의 기본 단위이며, 등록된 시료만 주문 가능하다.

#### 4.2.1 시료 등록

**입력값**

| 필드 | 타입 | 설명 |
|------|------|------|
| 시료 ID | 문자열 (고유) | 시스템 내 식별자 |
| 이름 | 문자열 | 시료 명칭 |
| 평균 생산시간 | 숫자 | 시료 1개 생산에 걸리는 평균 시간 |
| 수율 | 0 < 실수 ≤ 1 | 정상 시료 수 / 총 생산 시료 수 (예: 0.9) |

#### 4.2.2 시료 조회

- 등록된 모든 시료 목록을 표시한다.
- 각 시료의 현재 재고 수량을 함께 표시한다.

#### 4.2.3 시료 검색

- 이름 등 속성 기준으로 특정 시료를 검색한다.

---

### 4.3 시료 주문 (예약)

주문 담당자가 고객 요청을 시스템에 등록한다.

**입력값**

| 필드 | 설명 |
|------|------|
| 시료 ID | 주문할 시료 식별자 |
| 고객명 | 주문 고객 이름 |
| 주문 수량 | 요청 수량 |

- 등록 즉시 주문 상태는 **RESERVED**가 된다.

---

### 4.4 주문 승인 / 거절

생산 담당자가 RESERVED 상태의 주문을 처리한다.

#### 4.4.1 접수된 주문 목록

- RESERVED 상태의 주문 목록을 표시한다.

#### 4.4.2 주문 승인

재고 상황에 따라 자동으로 두 가지 경로 중 하나를 처리한다.

| 조건 | 처리 결과 |
|------|-----------|
| 재고 ≥ 주문 수량 | 즉시 **CONFIRMED**로 전환 |
| 재고 < 주문 수량 | 생산 라인 큐에 자동 등록, **PRODUCING**으로 전환 |

#### 4.4.3 주문 거절

- 특정 주문을 즉시 **REJECTED** 상태로 전환한다.

---

### 4.5 모니터링

담당자가 시스템 현황을 한눈에 파악할 수 있는 화면을 제공한다.

#### 4.5.1 주문량 확인

- 현재 상태별(RESERVED / PRODUCING / CONFIRMED / RELEASE) 주문 목록을 표시한다.
- REJECTED 상태는 표시하지 않는다.

#### 4.5.2 재고량 확인

- 각 시료별 현재 재고 수량을 표시한다.
- 주문 대비 재고 상태를 아래 기준으로 구분하여 표기한다.

| 상태 | 기준 |
|------|------|
| 여유 | 주문 대비 재고 충분 |
| 부족 | 주문 대비 재고 수량 부족 |
| 고갈 | 재고 수량 = 0 |

---

### 4.6 생산 라인

#### 4.6.1 생산량 계산

주문 승인 시 재고 부족분을 생산하되, 수율과 오차를 반영한다.

```
실 생산량 = ceil(부족분 / (수율 × 0.9))
총 생산 시간 = 평균 생산시간 × 실 생산량
```

- 생산 완료 시 해당 주문 상태를 **PRODUCING → CONFIRMED**로 변경한다.

#### 4.6.2 생산 현황 표기

- 현재 생산 중인 시료 정보를 표시한다.
- 표시 항목(예시): 주문 정보, 현재까지의 생산량 등 (구현 자율)

#### 4.6.3 대기 주문 확인

- 생산 큐에서 대기 중인 주문 목록을 표시한다.
- 스케줄링 전략: **FIFO** (선입선출)

---

### 4.7 출고 처리

- CONFIRMED 상태의 주문에 대해 출고를 실행한다.
- 출고 실행 시 주문 상태를 **CONFIRMED → RELEASE**로 전환한다.

## 5. 비기능 요구사항

### 5.1 아키텍처

- **MVC(Model-View-Controller)** 패턴을 적용한다.

### 5.2 데이터 영속성

- **JSON** 파일을 사용하여 데이터를 저장하고 불러온다.
- 시스템 재시작 후에도 데이터가 유지되어야 한다.

### 5.3 인터페이스

- **콘솔(CLI)** 기반으로 동작한다.
- 담당자가 직접 명령을 입력하여 시료 등록 및 주문 처리를 수행한다.

## 7. 용어 정의

| 용어 | 정의 |
|------|------|
| 시료 (Sample) | S-Semi가 생산·납품하는 반도체 샘플 단위 |
| 수율 | 정상 시료 수 / 총 생산 시료 수 (0 < 수율 ≤ 1) |
| 생산 라인 | 웨이퍼 공정 설비 흐름; 시료를 한 번에 하나씩 생산 |
| 생산 큐 | 생산 대기 중인 주문 목록; FIFO 방식으로 처리 |
| 출고 | 완성된 시료를 고객에게 납품하는 행위 |
